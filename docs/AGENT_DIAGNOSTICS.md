# 脱敏模型决策诊断

2026-10-22 增量，基线 c718947。目标是让核查失败可以定位，同时不保存被拒绝的模型内容。首轮真实模型 missing-prior 的原始内容没有保留，**本增量不能倒推出当时哪一个字段错了，也不关闭 FE-013**。

## 接口

模型决策校验失败时，Agent 异常和本地 `/api/run` 响应增加可选字段：

```json
{"decision_diagnostics": [{"call": 1, "category": "ARGUMENT_KEYS"}]}
```

| category | 含义 |
|---|---|
| INVALID_JSON | 不能解析为 JSON |
| DECISION_SCHEMA | 顶层字段或 tool/arguments 类型不符合契约 |
| UNKNOWN_TOOL | 工具不在允许清单内 |
| ARGUMENT_KEYS | 参数字段缺失或多出 |
| ARGUMENT_VALUE | 参数值的类型、长度或允许枚举不符合契约 |

只有固定类别和从1开始的调用序号，没有原始工具名、字段名、参数值、模型原文、问题或文档内容。没有文件日志或新增持久化数据库。正常请求不携带空诊断字段。已有 AGENT_FORMAT / AGENT_TOOL_REJECTED 状态码保持。

第一次格式修复若成功，响应仍保留发生过的类别；修复后网络失败也保留已有类别，失败请求用量照常计入且缺失用量为 unknown。诊断列表只属于当前请求。格式修复仍至多一次，算在总计四次调用中；不重试未知工具、不放宽参数、不替模型推断缺失年份。

## 可复跑的离线效果

```sh
python3 -m unittest tests.test_agent_diagnostics -v
python3 scripts/check_decision_compatibility.py
python3 -m unittest discover -s tests -v
python3 scripts/evaluate.py --output evaluation-result.json
```

- 12 个预先列出的协议故障输入，固定类别可观察覆盖从基线 **0/12** 变成 **12/12**。同一组真实回环 HTTP 请求也为 **12/12**，全部422且金融输出为空；敏感测试标记回显 **0/12**。
- 5个新增测试方法在旧代码上产生26个失败断言；修复后5个通过。正常跨请求隔离对照原已通过，不把它冒充新修复。
- 349个离线协议组合与基线比较：允许／拒绝和外层状态码 **349/349** 一致，包括11个接受组合。诊断分类没有扩大权限。
- 本地完整 **181** 个测试通过（20.523秒）；固定合成业务任务仍 **8/8**；JS **7** 项含24组Python对照通过。
- 本轮付费调用 **0**。测试使用明确标注的协议夹具，不能推断真实模型失败率下降；首轮真实8题仍是 **7/8**，原题集、原始结果和评测规则未改。

兼容对照脚本读取固定的可信历史提交c718947中的校验函数，只用于开发检查，不是运行时工具；浅克隆需要先取得该提交。它不执行模型生成代码。

类别覆盖衡量“是否能区别失败发生在哪个校验层”，并非金融问题准确率或人工节时。349组合不是完整输入空间或模糊测试证明。此前真实失败可在下次经授权调用时用新字段收集更精确证据，再决定是否需要改进提示或工具契约。

## 数据流与审查点

`_decision` 在对应拒绝分支抛出带固定 category 的 DecisionError → `_execute` 记录调用序号 → `run_agent` 将记录附到成功结果或异常，并保留失败计量 → HTTP handler 将诊断加入空金融结果。`scripts/evaluate.py` 已保留整份响应，因此未来运行报告自动携带该字段。

检查时不要把 rejected 原文、无效字段名、完整参数或来源片段加入 category；不要将所有拒绝一律计为业务成功。FE-013仍待真实语义复核。公开Pages无模型服务，本字段只在本地模型链和离线测试中出现。
