# 金融证据交接：两轮需求与竞品取舍

访问日期：2026-10-22（Asia/Taipei）。以下是官方产品说明和案例，不是对竞品的亲测或采购评估。岗位层级/招聘门槛不在本轮证据范围。

## 第一轮：需求是否真实，已有产品做到了什么

| 来源与适用范围 | 可核验事实 | 本项目可承接的具体问题 |
|---|---|---|

恒生所报告的效果属于其特定合成 PoC；不移植为 FinEvidence 的准确率。文档未提及某能力，不等于竞品没有该能力。本轮没有竞品账号或同条件计时实验。

## 第二轮：反驳方案后选择什么

1. 复制全能金融研究聊天：难以在没有获许可内容库的前提下形成优势。本轮不扩张金融覆盖声明。
2. 添加通用 PDF/OCR：仅导入文字不能证明财务转录和页码正确；真实报告权利、物理页码与人工确认仍是下一重要缺口。
3. 只导出 JSON：文件可解析，并不能发现其中金额、单位或引用被改动。
4. 因而扩展现有核查→原文→备注→导出路径，加入独立的**复算交接包**：接收者用当前受信样本重新执行允许的确定性工具，核对结果、事实、完整引用与原文，下载差异报告。

设计目标是可检查、可复跑的窄场景能力，不是超越竞品整体。可量化假设：在固定人工构造的改动集合上，单纯 JSON 解析会接受全部改动；本功能应拒绝这些差异，并接受未改动的已知结果。该对照不是任何竞品的真实实现。

## 边界与产品取舍

- 在 GitHub Pages 和本地 Python 工作台均可使用。文件只在接收者浏览器读取，最多 256 KiB；不会上传，也不会调用模型。
- 只复算明确支持的工具和资料版本；不执行文件指定的代码、URL 或 Agent。原始执行记录继续独立保留，模型轨迹不由此协议认证。
- 包内原文不是新的可信来源：复核使用当前部署已校验的资料包。资料版本不同即拒绝，代码版本不同提示；没有历史代码自动执行。
- 备注和勾选只是未经认证的交接信息。没有签名、身份、审批或合规认证；整体替换成另一份自洽合法包也不能证明恶意。
- 需要真实企业使用时，下一验收对象应是有授权的真实报告、人工转录核验、组织权限和持久审计，不能通过界面措辞跳过。
